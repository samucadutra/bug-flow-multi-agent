# Report Template

Pinned structure of `eval-report-<ISO-timestamp>.md`. The skill writes the file by filling in this template; do NOT alter the section order or headings — `only failed-last-run` parsing and human cross-run diffs depend on shape stability.

The **chat summary** is a compact projection of this same template: header (status line, item / AC aggregates, defensive insight when triggered), then only the FAIL / `⊘` ACs, then only the FAIL / BLOCKED items in their own short blocks, then the path to the file report. Everything else from the template (Discovery, Pre-run cleanup, full Pre-flight, full Coverage Manifest, PASS items, Evidence, Overrides, Soft-fails) lives in the file only.

Placeholders are written as `<like-this>`. Lists with no entries collapse to a single italic line `*(none)*` rather than an empty section.

## Notes for the writer

- **Run-id format**: ISO 8601 normalized to filename-safe form, e.g., `2026-04-28T17-32-04Z`. The same string appears in the filename, the `**Run:**` line, the ephemeral DB name (`eval_<feature-id>_<run-id>`), and the tmpdir (`evaluator-<feature-id>-<run-id>`). `<feature-id>` follows the marker definition pinned in SKILL.md Step 3 (lowercased `F<N>` prefix).
- **Item ordering inside a surface**: document order from `contract.md`. Do not re-sort by verdict.
- **Evidence collapse**: always wrap raw evidence in `<details>` so the report is skimmable at the headline. Trim bodies to the parts that matter for the asserted bullets — full request / response dumps add noise.
- **Defensive insight threshold**: ≥ 80 % of *executed* items (not counting BLOCKED, MANUAL, SKIPPED) failing with the same root-cause pattern. Compute on actually-executed items only.
- **Cross-run diffability**: `diff` between two timestamped reports should highlight only what truly changed. Keep section headings, table column order, and bullet shapes byte-stable across runs.
- **Chat summary projection**: header lines verbatim, then a `## Failures` section listing each `✗` AC (one line: AC verbatim, mark, item IDs with short reason) and each FAIL / BLOCKED item (one line: ID, title, one-line root cause), then `Report: <relative path>`. Nothing else.
